WebAI at Home / account key experiments

Can this browser tab hold
an account key pair?

The de-risk gate of the accounting system in issue #122. This page generates a key pair whose private key the browser refuses to hand back, keeps it in IndexedDB across page reloads and browser restarts, and signs a random challenge inside a message that names this project and this purpose. The signature is verified here, and then again in Node.js by tools/verify_account_key_signature.js, which is where the gateway would verify it.

How to run the whole gate

  1. Open this page. It generates and stores a key pair on the first visit.
  2. Reload the page. The log must say the key pair was read back from IndexedDB.
  3. Quit the browser completely, reopen it, and open this page again. The log must still say the key pair was read back, with the same generation time and a higher load count.
  4. Copy the verification document below into a file and run node tools/verify_account_key_signature.js that_file.json.
  5. Repeat all of it in every browser the project asks volunteers to use.
